# AIchat-graph

以 SQLite 为唯一主存储的本地协作思考图。你与外部 AI Agent 讨论，Agent 整理节点和关系，
浏览器同步呈现思路；日后可以从完整独立 HTML 回顾。

程序提供 CLI、本机服务、图阅读器和 HTML 导出，不内置模型聊天、API 密钥或自主 Agent。
随附 Skill 提供讨论与记录方法；程序与 Skill 可以分别使用，各自带有 CLI 文档。

## 能做什么

- 每个主题有独立起点。全局主线在最左侧向下，分支向右展开，同源分支上下排列并共用干线。
- 完整显示卡片标题和连接说明；支持主题目录、搜索、详情、重要标记、当前讨论标记、折叠和阅读位置恢复。
- Agent 按需读取概览、结构或正文：概览／结构只给关系与元数据，正文单独读取；resume 提供当前卡片正文、来路与邻居。
- 单卡完整编辑、补旧卡并新建卡、链中插入及关系重排均可一次提交；也可删除叶卡。
- 写后返回节点新版本，便于直接继续修改；冲突时拒绝覆盖已变化的内容。
- CLI 可用 diff 核对最近一次写入的摘要、单卡字段与正文差异；`diff --input` 预览批量修改而不落库，预览也可用 --node --patch 展开具体差异。
- 图和主题详情显示最近一次内容批次：卡片标出新增／改动，清单还包含删除；
  可展开看字段与正文差异。只保留最近一批，不是历史；重要标记独立。
- 用户可为主题指定 HTML 保存位置；内容有变化时自动更新同一路径。
  成品内嵌导出时的最近一批变化，离线也能看标签与差异；程序或阅读器升级不会单独重写旧成品，移走后仍可离线阅读。

## 获取与打开（Windows 10／11 x64）

Windows 免安装包的文件名为 AIchat-graph-0.1.0-win-x64.zip。包内自带 Node 24.17.0
和生产依赖，解压后即可运行，不需要安装 Node、npm、Git、PowerShell 7、.NET 或 VC++。

1. 把 ZIP **完整解压**到可写、长期保留的目录（例如 D:\Tools\AIchat-graph）。
2. 双击 AIchat-graph.exe。
3. 第一次选择已有讨论库（含 graph.sqlite 的目录），或新建一个空文件夹。
4. 服务就绪后用默认浏览器打开阅读页；下次双击直接打开上次的库。

关闭网页不停止后台服务。页面「程序」菜单可重新选库或退出本库服务，也可运行
AIchat-graph.exe --stop。更新时从新 ZIP 运行「更新已有程序.cmd」，程序文件替换，
讨论库和本机 .aichat 设置保留。详细步骤见包内「开始使用.md」。

程序不注册系统服务、PATH、文件关联或协议，也不自动安装 Skill。包根 aichat.cmd
是给 Agent 使用的真实入口；Skill 是可选组件，安装不会改动讨论资料。

下载页/Release 发布后只上传这个 ZIP，不把本机配置或真实资料放入仓库。
维护者在仓库运行 npm run build 和 npm run package:windows，可在
.local/packages/ 得到同一 ZIP 与未压缩目录；ZIP 本身不提交到 Git。

## 源码运行与开发

环境要求见 package.json 的 engines；当前为 Node.js 24.17.0、npm 11.13.0，
SQLite 由 Node 内置模块提供。源码模式适合开发和构建，不是普通用户的必需步骤。

~~~sh
git clone https://github.com/THhapp/AIchat-graph.git
cd AIchat-graph
npm ci
npm run build
~~~

~~~sh
node ./dist/next/cli.js init "../my-graph-workspace" --name "My graph"
node ./dist/next/cli.js open --workspace "../my-graph-workspace"
~~~

Windows 可用 .\aichat.cmd 替代 node ./dist/next/cli.js。
工作区、默认库和旧资料导入见[工作区指南](docs/workspace.md)。
一边使用一边开发时，start.cmd 运行已安装的日用便携程序，start-dev.cmd 使用独立开发库；
构建、打包、更新与宿主安装见[开发说明](DEVELOPMENT.md)。

## 与 Agent 一起使用

把实际程序入口、工作区和讨论目标交给 Agent。便携包的 aichat.cmd 是真实入口，
它使用包内 Node 与生产依赖；源码模式可用 dist/next/cli.js。
它可直接按[程序 CLI 手册](docs/cli.md)工作；需要讨论组织与节点写作方法时，
再使用随附 [Skill](skills/aichat-graph/SKILL.md)（程序不依赖 Skill，首次打开不安装）。

进入未知主题可先读概览；已知节点可直读正文；续谈可用 resume。
想核对上一次写入改变了什么，可用 diff 看批次摘要或单卡字段／正文差异；普通续谈不必每次先看差异。
Agent 使用稳定节点 ID 与持久版本提交修改，程序负责结构校验、事务和图更新。
程序不读取其他聊天窗口，也不自行判断哪些内容值得记录。

启用后，同一对话持续绑定实际 topicId；页面切换主题不改变其他 Agent 对话的记录目标。
保留日后理解与继续讨论所需的认识、理由、证据和有价值的问题，优先完善已有节点。
值得独立返回的后续问题用 next，独立方向用 branch；一次回复可以不修改图。
临时操作与常规进度通常留在聊天中，影响认识或结论时再保留必要部分。

### 最小启动任务书

填好占位内容后交给 Agent；已有主题可直接使用页面“复制给 Agent”的信息。

~~~text
请启用 AIchat-graph 记录，陪我开展讨论。

实际 CLI 入口：【便携包 aichat.cmd；源码开发用 dist/next/cli.js】
工作区：【实际讨论目录】
主题：【已有主题名称或 ID；新建时填写名称及可选 key】
起始问题：【讨论目标】
可选 Skill：【名称或 SKILL.md 位置；不用则留空】

核对指定主题并在本对话沿用；明确要求新建时才创建主题和独立起点。
使用指定版本的 CLI 读取和维护，不自行安装 Skill、重建程序或迁移资料。
正常回答问题，只记录值得继续的认识与问题，优先融入已有节点。
临时操作与常规进度通常不入图；无实质变化可不写，不逐句转录或生成逐轮报告。
~~~

工作区已配置为该程序的默认目标时，可用 --workspace-id 核对身份；
它不负责查找目录。没有默认绑定时仍需给出 --workspace。

## 数据、成品与知识

工作区包含：

~~~text
graph.sqlite                     主题、节点、正文、关系、版本与请求结果
resources/                       正文明确引用的本地图片
.aichat/runtime/service.json      本机服务地址和实例
.aichat/local/runtime.json        本机稳定端口偏好
.aichat/local/exports.json        用户指定的 HTML 保存位置
~~~

SQLite 正文使用 Markdown 语法，不存在日常维护的节点 .md 文件。
旧版 V2 / isolated 资料可以一次性导入，原件保留；正常运行不再读写或监听它们。
首次使用新库无需导入，已有 graph.sqlite 不要重复初始化或导入。

在页面导出设置中选择工作区与程序目录之外的绝对 .html 路径，父目录须存在。
HTML 包含完整主题、分支和阅读资源；生成失败保留旧成品，外部改动的目标不直接覆盖。
它是只读快照，打开后不自动联网更新；要看新成品需重新打开或刷新文件。

独立知识 Markdown 在需要时由 Agent 提炼；不要求同时维护两份相同正文。
正文支持代码、表格、公式及受限本地图片，不提供通用附件管理或网络图片抓取。

## 当前边界与隐私

- 服务监听本机环回地址，不提供多人同步、公网认证或远程协作。
- 深层分支或长说明会使图变大，需要缩放或拖动；“查看全部”主要用于看结构。
- 搜索定位不会自动展开折叠祖先；可先展开或查看全部。
- 主要面向 Windows 本地使用；移动端、Obsidian 内嵌及超大图体验未作完整确认。
- 项目不内置遥测、模型调用或云同步；外部 Agent 的模型请求由所用宿主及其配置决定。
- HTML 包含折叠或当前不可见的节点，分享前需检查整份内容、资源和本机定位信息。

安全问题报告方式见[安全说明](SECURITY.md)。
