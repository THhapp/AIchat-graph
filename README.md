# AIchat-graph

以 Markdown 为源的本地协作思考图。你与外部 AI Agent 讨论，Agent 维护节点和关系，浏览器同步呈现思路历程；也可导出独立 HTML，供日后回顾。

项目不内置模型聊天、API 密钥或自主 Agent。

程序提供 CLI、本机服务、图阅读器和 HTML 导出；随附 Skill 提供外部 Agent 的协作与记录方法。
程序可独立使用，Skill 通过实际程序入口操作工作区，两者各自附带 CLI 文档。

## 能做什么

- 按主题组织讨论，每个主题有独立起点和编号，节点各自保存为 Markdown。
- 每个主题的全局主线固定在最左侧，沿 `next` 从上到下连续阅读；`branch` 统一向右展开，同一来源的多个分支在右侧上下排列并共用一条竖向干线，分支内部继续纵向推进。
  图上标题完整显示，连接说明写在自己的支线旁。
- 从左侧主题目录打开对应的图，分别保留阅读位置、选择、卡片折叠与目录折叠状态。
- 外部 Agent 按需读取和整理已有节点，通过版本检查避免覆盖过期内容。
- 卡片上可直接设置或取消重要，用户与 Agent 读写同一份源数据；每个主题最近一次实际内容更新涉及的卡片会自动提示。
- 每个主题可指定 HTML 保存位置，内容有效更新后自动生成完整的单文件快照。
- 实时页面和离线 HTML 支持 Markdown、代码、表格、公式与受限本地图片。

## 安装与运行

当前提供源码，需要 Node.js 和 npm。已验证环境为 Node.js 24.17.0、npm 11.13.0；尚未提供独立安装包。

```sh
git clone https://github.com/THhapp/AIchat-graph.git
cd AIchat-graph
npm ci
npm run build
```

选择仓库之外的目录保存讨论资料。仅对不存在的新目录执行初始化；已有工作区直接启动服务。

```sh
node ./dist/cli/index.js init "../my-graph-workspace" --name "My graph"
node ./dist/cli/index.js serve --workspace "../my-graph-workspace"
```

Windows 也可直接使用仓库根目录的 `aichat.cmd`；日用固定版本目录同样提供 `aichat.cmd`，不需要先安装 Skill。
打开 <http://127.0.0.1:4317>，在服务终端按 Ctrl+C 停止。服务仅监听本机环回地址；端口冲突会明确报错。

## 与 Agent 一起使用

给外部 Agent 实际程序入口和工作区路径，它可以按 [程序 CLI 手册](docs/cli.md)及命令帮助接入。
需要本项目的讨论组织、节点写作与共识记录方法时，再使用随附的
[Skill](skills/aichat-graph/SKILL.md)。Skill 可从项目读取或按宿主需要安装，
是协作指引，不是自动注入每次对话的后台钩子。

Agent 将讨论整理为节点正文与连接，通过 CLI 提交给本机服务；服务检查版本和结构，
事务保存 Markdown，再通知浏览器取得有效图数据。前端负责坐标、连线、标签和卡片呈现。
程序不直接读取外部聊天窗口，也不自行决定哪些内容应记入图。

启用记录时，可以说“这次记录到论文阅读这个主题”。Agent 核对实际主题并绑定后，在当前对话持续沿用；重名或目标不明确时再询问。新主题可以创建独立起点。

继续已有讨论时，从页面选择主题，点击“复制给 Agent”，将定位信息粘贴到对话中。前端切换主题只影响浏览，不改变其他 Agent 对话的记录目标。

随附 Skill 按思考单元组织记录：同一问题原位完善，后续问题纵向继续，独立方向形成侧枝。
不逐句复制聊天，也不要求每轮新增节点。新提议、讨论认可与参考资料分别标记；
认可不代表已执行、实测或掌握。这些是协作方法，程序校验的是数据结构与提交条件。

程序入口、完整命令、读取凭据和冲突恢复见 [程序 CLI 手册](docs/cli.md)；
讨论图维护流程和 Skill 自带命令参考在 [Skill](skills/aichat-graph/SKILL.md)。
CLI 应对应实际运行服务的接口；使用 Skill 时，其命令参考也须适配该接口。

读取已有主题时，Agent 先取得主题概览（主线与直接分支入口），再按需读取局部结构或正文；多卡正文由程序按整次响应预算分页，续读标记原样交回即可，不要求 Agent 自行维护各卡偏移。

### 最小启动任务书

填好占位内容后粘贴给 Agent。程序运行目录须对应实际服务：源码运行填仓库根目录，固定版本填其 `.local/daily` 的绝对路径。

```text
请启用 AIchat-graph 记录，陪我开展以下讨论。

程序运行目录：【实际运行版本的绝对路径】
工作区：【讨论工作区的绝对路径】
可选 Skill：【已安装 Skill 名称或 SKILL.md 路径；不用则留空】
主题名称：【显示名称】
主题目录名：【自命名单层目录，可用中文】
讨论目标与起始问题：【填写内容】

使用同目录下的 dist/cli/index.js，通过 node 调用，并显式指定 --workspace。
从 version、命令帮助和程序运行目录下的 docs/cli.md 核对实际接口。
指定了 Skill 时读取并使用它；未指定时直接按程序手册接入，不自行安装 Skill。
核对已有主题与运行服务；服务未启动时，允许使用同版本 CLI 启动这个已有工作区，不重新初始化。
通过 create-topic 创建指定主题目录和独立起点；若目录已存在，核对身份后续谈，不覆盖或另建副本。

绑定本对话的主题，随讨论持续整理图；使用 Skill 时沿用其协作方法。
保留必要解释、理由和实例，不逐句转录聊天，也不生成额外状态文档。
完成接入后直接开始讨论。
```

主题目录由 CLI 创建在 `<工作区>/topics/<主题目录名>`，无需提前建空文件夹。已有主题续谈可直接使用页面“复制给 Agent”的信息。

## 资料与导出

工作区保存真实 Markdown，程序缓存和运行状态位于 `.aichat/`，不显示为图节点。资料库应独立于源码和构建产物保存。

`init` 还会为新工作区生成接入指南 `AGENTS.md`，只说明该资料库的定位与操作边界。
它可承载资料库本地约定；更新程序不会覆盖已有工作区的指南或用户补充。

```text
workspace.json
topics/<主题目录>/topic.md
topics/<主题目录>/<nodeId>.md
.aichat/
```

在页面的“导出”设置中指定工作区及程序目录之外的绝对 `.html` 路径，父目录须存在。程序在内容有效更新后替换同一路径成品；生成失败保留旧文件，外部修改的文件拒绝覆盖。

HTML 包含完整主题、分支、脚本、样式和必要资源，移走后可离线阅读；它是只读快照，不自动联网更新或写回源记录。需要提炼知识时，可从实体 Markdown 单独整理，不要求长期维护两份相同正文。

## 限制

- 当前只支持一节点一份 Markdown、每个主题独立根的格式 2；旧格式 1 与跨主题 shared 工作区不再读取或迁移。
- 图片支持明确引用的工作区 resources 内 PNG/JPEG/GIF/WebP 或安全 raster data URI；单图 8 MiB、总计 32 MiB。不抓取网络图片，
  不提供通用附件管理。
- 搜索定位不会自动展开折叠祖先，可先展开或点击“查看全部”。
- 层级较深或分支说明很长时，图会向右、向下展开得更大，需要缩放或拖动浏览；关系说明完整显示并占用自己的空间，长说明会把相邻卡片拉开，而不是被截断。旧数据里的 `side` 仍保留在源文件，
  但界面统一向右呈现。
- 主要验证 Windows 本地环境；Obsidian 应用内嵌、移动端和大规模性能尚未验证。
- 不含多人同步、云服务或数据库。

## 数据与隐私

讨论资料保存在自己选择的本地工作区；运行缓存和导出绑定位于工作区的 `.aichat/`，浏览器用本机存储保留阅读状态。项目没有内置遥测、模型调用或云端同步。外部 Agent
是否将讨论内容发送给模型提供方，取决于你使用的 Agent 及其配置。

独立 HTML 包含整个主题的正文、分支和必要资源，包括当前折叠或未显示的内容；隐藏卡片不等于删除或脱敏。分享 HTML、截图、工作区或问题报告前，检查其中的个人信息、源文件路径和引用内容。
安全问题的报告方式见 [安全说明](SECURITY.md)。
