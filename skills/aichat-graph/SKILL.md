# AIchat-graph 协作思考

让讨论留下可理解、可继续的思考图。程序负责 CLI、存储、布局与成品，
本 Skill 负责讨论和记录方法，并附有独立命令参考。

## 按需查阅

- 首次接入或选主题：[接入与主题绑定](references/workspace.md)。
- 撰写和整理节点：[节点内容与维护分寸](references/maintenance.md)。
- 参数、NodePatch、batch、分页和错误：[命令参考](references/commands.md)。

已读且仍在上下文中的规则直接沿用，缺什么补读什么，不每轮重读全部文件。

## 目标与讨论

从实际入口和配置确定工作区，按用户意图绑定稳定 topicId。
--workspace 给目录，--workspace-id 只核对身份；页面选中和其他对话不替代当前绑定。
启用后持续按需维护，用户暂停则停止；不因记录任务自行安装、初始化或迁移。

聊天充分解释当前问题，节点保留能独立理解和继续的认识、理由与必要证据。
按需举例，不把例子或固定小节当成每卡必填；节点体量约定不限制聊天解释。
什么值得入图：日后值得回看、能独立理解并可继续推进的问题与认识，不按认可等级给卡片分类。
认可、实施、实测和掌握在正文中分别表述；important 是独立的回看标记。

## 随讨论维护

1. 对照本轮实际问题定位记录，修改前理解相关正文与邻接关系。
   未知主题可读 overview，已知节点可直接 read --node；
   返回旧问题用 resume，按需再读正文，不机械逐层展开。
2. 同一问题原位完善，下一步问题用 next，可独立返回的方向用 branch。
   同一主题不等于同一张卡，不按轮次建卡，也不把新问题一直追加在旧卡末尾。
3. 将补充融入对应位置，清除失效或重复叙述；同步标题、概述和连接理由。
   单卡完整修改用一次 edit，混合多卡用 batch；插入、纯重连和叶删除有各自入口。
4. 确认提交成功及实际受影响节点。继续修改可用 nodeRevisions[nodeId]，
   不只为取版本重复读取；需要理解变化或遇到冲突时再读。
   无实质变化可不写，成功后自然继续讨论，不固定汇报记录过程。

## 操作要点

- 节点正文保存在 SQLite，仍使用 Markdown 语法；不直接改库或手动双写 HTML。
- 节点没有确认状态，写命令也没有 --state；不要按旧版习惯给卡片分认可等级。
- 修改使用实际读取或上次写回的节点版本；412 后重读并重新判断，不偷取最新版本覆盖。
  独立 important 设值可仅给 ID，其余写入条件按命令参考。
- 长文本使用宿主容易可靠传递的文件或显式 stdin，不额外制造多层包装。
- page.next 原样交回 --cursor；结果未知先查原 requestId 的 status。
- 参数不明确时查 `help <command> --json` 或随附参考，不反复加载整套帮助。
- 提炼知识、附件处理按实际需要进行，不另建逐轮副本、维护日志或知识库全文双写。

Skill 是工作指引，不是自动注入每轮回复的后台钩子。
