# AIchat-graph 协作思考

让讨论留下可理解、可继续的思考图。外部 Agent 参与讨论和维护源记录，实时界面用于跟进，独立 HTML 用于回顾。

## 讨论与记录的分工

- 聊天中完整表达当前问题所需的解释、理由和例子，用户不必打开节点才能理解回答。不能用“已记录到图中”代替说明，也不必把全部旧节点正文重复粘进聊天。
- 图在后台整理可继续的思考内容，文件维护不应把交流变成反复批准、等待更新和阅读维护汇报。必要解释应充分准确，不靠压缩篇幅或删掉条件换取简洁。
- 节点聚焦一个明确内容，同时能够脱离当轮聊天阅读。编写节点时概述说明要点，正文保留必要解释，具体外部例子用独立引用块，有明确共识时用“已形成的共识”小节保存相关结论与限制。首次组织这些内容时读[节点内容与维护分寸](references/maintenance.md)，后续沿用，不每轮重读。

## 启用与定位

- 用户启用指定工作区的图记录后，在该讨论范围内持续按需维护，普通讨论也适用；用户暂停记录时停止写入。
- 从用户提供的信息、已配置命令或宿主实际加载的工作区入口取得 CLI 和工作区位置。工作区不等于工具源码目录或当前 shell 目录。目标明确就沿用；缺失或存在多个目标时只澄清实际歧义，不猜目录。
- 用户可直接说主题名、给出目录或续谈节点，也可粘贴前端“复制给 Agent”的定位信息。首次用 `topics` 核对真实主题并绑定稳定 topicId；唯一匹配后持续沿用，不每轮确认。重名或多个可能目标时只问实际歧义。详见[主题选择与绑定](references/workspace.md#主题选择与绑定)。
- 用户明确换主题时才切换本对话的记录目标；前端浏览选择、全局 activeNode 或其他聊天的焦点不代替绑定。用户明确要求记录新主题时可 `create-topic`，不自动每聊天建主题。
- 首次接入、换工作区或入口不明时，读[工作区与目录职责](references/workspace.md)。Skill 不代替初始化、迁移、安装、批量提炼或服务管理的授权；已有具体授权可以沿用。

## 图的含义

- **主题**组织一个完整、可持续的问题，可以跨多次聊天。新工作区的主题各有独立根和编号；目录组织内容，旧库的 shared 模式仍按实际结构读取，不自动转换。
- **节点**是可辨认、能继续展开的思考单元，不等于消息、段落或任务。一张节点可多轮完善，一轮也可维护多个节点。
- **next**沿当前线索纵向推进；**branch**侧向展开独立方向，分支内部仍可继续 next。保留已有主线，不因新增旁支挤掉后继。
- **连接描述**用简短关系句说明为什么从来源接到目标，例如“用实例检验尺寸公式”，而非仅写“展开”“相关”或重复标题；长理由放节点正文，具体尺度见内容维护说明。
- **proposed / agreed / reference**表示尚未确认的提议或判断、用户明确确认的讨论内容、资料与一般解释。状态不表示用户已经执行、实测或掌握；新提议不继承来源的 agreed。
- 实体节点 Markdown 是维护源；HTML 是生成的阅读成品。读取和修改源记录，不从庞大的 HTML 恢复正文或手工同步成品。用户浏览选择不限制 Agent 读取相关源记录。

## 每轮判断与整理

在已启用的讨论中判断本轮是否产生值得留下的认识、理由、条件、例子、澄清、修正或可返回的方向。这不是每轮必须调用工具的流水线。

有变化时：

1. 在已绑定主题内定位，按需读取节点正文及相邻关系。搜索用 `--topic <topicId>`，使用节点引用前确认属于当前主题。确有当前任务理由可跨主题读取，但不因此切换记录目标；主题边界不是读取权限屏障。不要只凭摘要修改未读过的解释，也不要为小改动读取全图。
2. 同一问题的补充、解释、例子和修正优先原位完善；沿当前线索进入后续问题用 next；可独立返回讨论的侧向内容用 branch。不能按聊天先后持续串 next，也不为展示横向结构机械建 branch；分支内部仍可 next。
3. 保留理解现状所需的理由、条件与关键转折。普通纠错和表达改善可覆盖；重要判断改变时保留必要来路，不复制每版全文。核对本次涉及节点的概述、正文、共识与连接描述是否仍一致，不把候选提议写成共识。
4. 在本轮答复结束前完成必要维护，核对提交结果。已有状态字段仍按实际格式维护，不能仅改正文却让状态表达相反含义。托管写入已校验结构，不例行重复全图校验或全套测试；直接改源文件后、诊断异常或怀疑结构损坏时再检查。

没有实质变化可以不写。不制造空节点、日期流水、逐轮副本或固定的“已更新”汇报，讨论自然继续。保存失败、冲突未解决或影响用户意思的歧义必须说明。

必要代码、公式、表格和实例条件不能压成标签；不设固定字数或全套填空模板，没有共识不造共识占位。节点出现新的独立方向时再判断是否分支，必要解释较长本身不是拆卡理由。

## CLI 操作边界

首次实际操作、命令不熟悉或遇到错误时，读[命令速查](references/commands.md)，按需查当前 CLI 的 `--help`。

- 显式指定工作区，先小范围读取再写入；身份、哈希、路径和默认顺序交给工具处理。
- 在线凭据必须来自真实读取版本。冲突后重读、重新判断，不能自动补最新哈希绕过检查。
- 结果不明先查原 requestId 并核对源内容，不盲目换身份重复提交。
- 长正文用文件或 stdin，避免长命令行和大量转义。同一批修改不要混用托管提交与直接编辑。
- 服务不可达仍可离线读源；说明对本次保存的影响，可继续讨论。启动、直接编辑或恢复操作沿用已有授权，不默认自动安装或迁移。
- 日常不需要附件；用户特别说明时按实际能力处理。不自行扩展附件库、备份系统或知识库双写。

Skill 是行为指引，不是每轮必执行的后台钩子。新聊天从实际可见入口确认工作区与维护约定，不依赖上一聊天的隐藏记忆。
