# 节点内容与维护分寸

首次组织主题或遇到记录尺度问题时阅读。操作参数见[命令速查](commands.md)。

## 节点该承载什么

一个节点承载可辨认、可继续的思考单元。按内容保留：它回答的问题或表达的认识，理解所需的条件、理由、推导和例子，引用资料或真实反馈的依据，以及值得返回的不确定方向。无需每张卡填满同一组栏目。

标题用具体问题或概念，不用日期、“本轮更新”或与状态重复的“已确认”等提示。正文可有必要的 Markdown、代码、公式、表格和列表，不假定原始 HTML 或脚本可以执行。

读者应能脱离当轮聊天理解：把“上面第二个”“这个”换成明确对象，保留实例初值、环境条件和适用范围。实验记录区分给出代码、用户已运行、实际观察、解释和尚待验证的猜想。状态不能代替事实证据。

## 原位、后继与分支

| 讨论变化 | 做法 |
| --- | --- |
| 同一问题补充解释、条件、例子或修正 | 原位完善 |
| 沿当前线索进入后续问题 | next；来源已有后继时先理解结构，不插队覆盖 |
| 有独立讨论价值的对照、假设、启发或侧向问题 | branch，并说明从来源展开的理由 |
| 一轮澄清了当前主题内多个已分开的思考单元 | 分别维护相关节点，不强行合成一张 |
| 解释较长，但仍是同一问题 | 保留必要解释，不单纯按长度拆卡 |
| 看好某方向但暂时没有精力实现 | 保留关注理由和可返回的问题，不自动变成开发任务 |
| 同意继续、重复表达或无实质变化 | 不必制造节点或更新 |

分支不以分歧为唯一条件。也不要求每次答复只落一处，或把所有 AI 联想都记入图。

例如，已有节点讨论卷积与池化后的张量尺寸，用户困惑展平后为何是 256：在明确实例参数后，补充 `[N,16,4,4]` 与 `16×4×4=256` 的联系，通常原位完善即可。若转向“改变输入分辨率后如何设计全连接层”，可另开分支。不能丢掉条件只记“展平是 256”，也不必复制整轮问答。

## 更新与保留来路

普通纠错、措辞改善可直接覆盖。重要判断改变时，判断覆盖后是否还看得懂为什么走到现在；必要时保留原判断的关键理由、改变依据及当前认识。不机械保存每版全文，不新建历史主题或备份目录。

未采纳、未实施和暂时不研究的方向可以有价值，但不必全部保留；以以后能否回顾、继续为判断，不以是否完成为标准。

不把同一结论复制到多个节点，不记录维护日志、日期流水或空的占位卡。

## 连接与状态

`description` 回答“从 A 为什么接到 B”，既不是目标摘要，也不自动声称因果或证明。改接来源后重新检查描述。

- `proposed`：提议或尚未确认的判断。
- `agreed`：用户明确确认的对应内容；不能用一声“继续”认可整组假设。
- `reference`：资料、外部证据与一般解释；事实依据仍需准确。

AI 的建议不自动成为共识。认可解释不等于实际执行，实际执行不等于结果已验证，更不等于用户已掌握。

## 记录与提炼

图可保留具体实例、疑问和思考联系。长期知识 Markdown 按需要另行提炼，不每轮双份维护，也不为每个节点建立对应知识笔记。

提炼去掉现场指代和维护过程，保留独立理解所需的条件、机制和例子；不把候选判断或未运行代码变成已证实事实。
