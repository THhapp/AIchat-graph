# 工作区与目录职责

首次接入、切换工作区或找不到入口时阅读。它不是每轮必做的扫描清单。

## 分清位置

| 位置 | 职责 |
| --- | --- |
| 工具／CLI 安装位置 | 运行产品命令，不存放用户思想 |
| 讨论工作区 | 实体主题、节点与工作区配置 |
| 主题 HTML 目标 | 前端指定、程序自动生成的阅读成品 |

知识库只在需要提炼时处理。不要把这些位置统一为当前 shell 目录，也不要把本机绝对路径固化进通用 Skill。

CLI 和工作区从用户给定入口、已配置命令或宿主实际加载的工作区约定取得。绑定明确就沿用；有真实歧义再澄清。新对话需要可见入口，不能假定任意目录的 AGENTS.md 都会被宿主加载。工作区入口可以保存稳定的位置和维护约定，无需复制整份 Skill 或记录每轮状态。

## 主题选择与绑定

用户可以直接说“继续 LeNet 学习”，也可以给主题目录、已有节点或前端“复制给 Agent”的定位信息。复制信息用于提供当前工作区、稳定主题 ID、真实目录、可选节点与程序入口；浏览器选中项本身不会自动改变任何聊天的记录目标。

首次接入时用 `topics --workspace "<工作区>"` 核对实际列表：

- 按用户给出的名字、目录或 topicId 定位；续谈节点先核对所属主题。显示名称不是身份，不要凭名称拼 ID 或文件名。
- 唯一匹配就绑定本对话的工作区和 topicId；后续按稳定 ID 沿用，不每轮确认。主题重命名不应被当成另一个主题。
- 重名时用真实目录、ID 或相关节点区别；只澄清影响本次记录的歧义，不让用户重新解释整张图。没有匹配不能默认为要新建。
- 用户明确要求新主题记录时，用 `create-topic` 在现有库中创建主题与独立根，取得返回的真实 ID 和路径后绑定。不因新开聊天、提到另一个概念或查看另一主题就自动创建或切换。

在绑定主题内搜索，用 `search "<词>" --topic "<topicId>" --workspace "<工作区>"`；读写节点时核对归属，不因另一主题的同名标题或相同显示编号选错节点。需要比较其他主题时可有目的地读取，不建立跨主题父边，也不把当前记录默默写进对照主题。主题隔离是组织和结构约束，不是假装 CLI 无权读取别的主题。

本对话的绑定来自用户意图与已核对的源记录，不使用工作区 activeNode 或前端当前浏览项猜测。只有用户明确换主题才切换；多段聊天可以各自绑定不同主题，无需写入全局 activeTopic。

## 入口与身份

使用已绑定 CLI，或 `node "<CLI入口>"`。开发构建入口通常是工程的 `dist/cli/index.js`；若使用隔离日用构建，应绑定 `.local/daily/dist/cli/index.js` 及该快照内同版本的 Skill。开发源码及其文档可能已变化，不能据此默认日用快照已经支持新接口。实际位置以用户和启动器提供的信息为准。

随 Skill 提供的 [aichat.ps1](../scripts/aichat.ps1) 只是仓库内转发脚本，从当前位置推导工程 CLI；**仅适用于保留仓库目录结构的使用方式**。把 Skill 复制到其他地方后，应使用实际 CLI 入口，不承诺该脚本仍可定位工程。脚本不启动服务、不构建、不复制业务逻辑。

```powershell
# 从 Skill 目录调用；PowerShell 7 和已构建的仓库可用时
./scripts/aichat.ps1 topics --workspace "<工作区>"
```

`whoami --workspace "<工作区>"` 核对运行服务与磁盘身份。没有服务时失败不等于源资料不存在，仍可用 `topics`、`read`、`validate` 离线读取检查。身份不符时先解决定位问题，不回退默认端口。

## 当前格式 2 的文件职责

```text
<工作区>/
  workspace.json
  topics/<主题目录>/
    topic.md
    <nodeId>.md
  .aichat/local/exports.json
  .aichat/cache/
  .aichat/runtime/
```

- `workspace.json`：工作区身份、格式版本、主题组织模式和讨论焦点；焦点不是本对话的主题绑定。
- `topic.md`：主题元数据，不聚合复制全部节点正文。
- `<nodeId>.md`：节点正文和邻近结构元数据，是真实维护源。
- `exports.json`：本机导出目标绑定，由前端／服务管理。
- `cache`：派生索引，不是思想正文。
- `runtime`：服务定位、锁与恢复信息，不能为解决报错随意删除。

实际路径使用命令返回结果；不要凭标题或显示编号猜文件名。字段与格式以当前产品契约和校验为准，本文件不维护第二套完整 schema。

新格式 2 工作区默认 `topicMode: isolated`：每个主题目录各有独立 root、主线和编号，父边不能跨主题。旧工作区缺省 `topicMode` 时按 `shared` 兼容，可能仍是一条跨主题的结构；不要仅凭一节点一文件就假定主题已经隔离，也不要自行改模式或移动文件来转换。

## 格式与操作范围

`topics` 或 `validate` 返回 `schemaVersion`。格式 1 仍可读，但不是一节点一文件；支持的写入方式见[命令速查](commands.md)。不自动迁移，转换始终隔离生成新目录。

推荐托管命令维护源记录。用户授权直接编辑时，先理解实际格式，同一批修改不要与托管提交并行，之后校验。不要通过手补哈希、清除恢复文件或改生成物绕过错误。

HTML 自动从有效源记录生成，不手动双写；读取内嵌全部脚本和字体的 HTML 会浪费上下文。只有用户明确提出实际附件需求时才处理资源，不预建附件库、归档或报告目录。
